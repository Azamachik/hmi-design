# ЛР 1 · Арабские цифры и пиктограммы, цветовое кодирование

Вариант 7 лабораторной работы по проектированию человеко-машинного интерфейса. Веб-приложение, в котором участник проходит тест, а результаты сохраняются в Postgres (Neon) и автоматически сводятся в отчёт с проверкой гипотез.

Стек: Next.js 16 (App Router), React 19, Tailwind 4, Neon (`@neondatabase/serverless`), zod. Деплой — Vercel.

## Гипотезы и тесты

| Гипотеза | Тест | Что сравнивается |
| --- | --- | --- |
| **1.** Арабские цифры воспринимаются лучше пиктограмм | **Тест 1.** Ряд пиктограмм, затем ряд цифр (порядок блоков случайный) | Самый длинный верно воспроизведённый ряд |
| | **Тест 2.** Смешанные ряды из цифр и пиктограмм | Какой вид элементов чаще оказывается в верном ответе |
| **2.** Яркие арабские цифры воспринимаются лучше тёмных | **Тест 3.** Яркие цифры, затем монохромные (порядок блоков случайный) | Самый длинный верно воспроизведённый ряд |

Пиктограмма — квадрат с точками по числу цифры, пустой квадрат — ноль. В тесте 3 каждая цифра всегда имеет свой цвет (цвета идут по радуге), а монохромные цифры — тёмные на светлом. Яркие цвета подобраны так, чтобы контраст с фоном был не ниже 3:1.

## Как проходит тест

Пробный ряд (в зачёт не идёт) и пять блоков, около десяти минут.

- **Блоки с растущей длиной** (тесты 1 и 3). Ряд начинается с 3 элементов, после верного ответа становится на один элемент длиннее, максимум — 9. Две ошибки подряд завершают блок. Результат блока — самая длинная верно воспроизведённая длина. Каждая попытка — новый случайный ряд.
- **Смешанные ряды** (тест 2). 6 рядов по 8 элементов: 4 цифры и 4 пиктограммы в случайном порядке. Можно ввести не всё, что запомнили. Ответ набирается клавишами обоих видов, поэтому в ответе видно, каким видом участник воспроизвёл каждый элемент.
- Ряд показывается целиком на `длина × 500 мс`, но не меньше 1,5 с. На ответ 20 с, потом ответ засчитывается автоматически.
- Значения в ряду не повторяются, цепочки вроде 3-4-5 отбрасываются: их запоминают одним куском.
- Ответ вводится только экранными клавишами того же вида, что и стимул — на компьютере и на телефоне цена ответа одинакова, а пиктограммы не приходится переводить в цифры.
- Порядок блоков внутри пар (пиктограммы/цифры, яркие/монохромные) выбирается случайно для каждого участника и записывается — так эффект тренировки не смешивается с условием.

## Что считает страница результатов

`/results` собирает всех участников и для каждого теста строит парное сравнение (у каждого участника есть значения в обоих условиях):

- среднее ± σ, медиана, минимум–максимум;
- сколько участников лучше справились с каждым условием, сколько поровну;
- парный t-критерий Стьюдента (двусторонний), p-value;
- вердикт: «подтверждается» (среднее в пользу гипотезы и p < 0,05), «скорее подтверждается» (направление верное, но различие не значимо), «различий нет», «скорее не подтверждается» / «не подтверждается» (обратное направление).

Итог по гипотезе 1: «подтверждается», если в обоих тестах среднее в пользу цифр, «частично» — если только в одном. Значимость показана отдельно у каждого теста. С малой выборкой (меньше 8–10 человек) значимости ждать не стоит, это нормально.

Кнопки на странице: скопировать сводку текстом (для отчёта), выгрузить CSV участников, CSV всех попыток, JSON. У каждого участника есть своя страница `/results/<id>` со всеми попытками. Страницы результатов публичные (без авторизации) — не вводите в поле имени ничего личного.

## Запуск локально

```bash
pnpm install
cp .env.example .env.local   # вписать строку подключения Neon
pnpm dev                     # http://localhost:3000
```

Без `DATABASE_URL` тест работает, но результаты некуда сохранять: в конце можно скачать их JSON-файлом, а `/results` покажет подсказку.

Параметры адреса: `/?t=700` — время показа на один элемент, мс; `/?a=30000` — лимит на ответ, мс. Остальные числа (длины, число рядов, число ошибок) — в [`src/lib/experiment/config.ts`](src/lib/experiment/config.ts).

Проверки: `pnpm lint`, `pnpm typecheck`.

## База данных (Neon)

1. Создайте проект на [neon.tech](https://neon.tech) и скопируйте строку подключения (Connection string, лучше «Pooled»).
2. Положите её в `DATABASE_URL` (локально — `.env.local`).

Таблицы `sessions` и `trials` создаются сами при первом обращении, миграции не нужны. Одна сессия — один участник; повторная отправка того же результата не создаёт дублей.

Очистить тестовые данные: в SQL-редакторе Neon выполните `truncate sessions cascade;`.

## Деплой на Vercel

1. Импортируйте репозиторий на Vercel и в **Root Directory** укажите `lab1` (в репозитории будут и другие лабораторные).
2. В **Storage** подключите интеграцию Neon — она сама добавит `DATABASE_URL`. Либо задайте переменную вручную в Settings → Environment Variables.
3. Deploy.

## Структура

```
src/
  app/                    страницы: тест (/), результаты (/results, /results/[id]), выгрузка (/api/export)
    actions.ts            server action: проверка и сохранение результата
  components/
    experiment/           экраны теста, клавиатура, слоты ответа
    results/              карточки сравнения, таблицы
    glyph.tsx             цифра или пиктограмма (SVG)
  lib/
    experiment/           ход теста: генерация рядов, движок блоков, состояние сессии (чистый reducer)
    analysis/             подсчёт очков, статистика, отчёт, CSV
    db/                   клиент Neon, запросы, схема
```

Ход теста — чистая функция состояния (`lib/experiment/session.ts`), случайность идёт от зерна, которое хранится в сессии. React-компонент только показывает состояние и ставит таймеры.
